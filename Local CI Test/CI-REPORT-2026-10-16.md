### Frontend environment notes

- The GitHub workflow pins Node 20. The local host used Node 24.19.0 and npm 11.17.0.
- Windows `tsx` could not read `os.userInfo()` in this host. Contract tests passed with a temporary local Node shim, which was removed afterward.
- The frontend fixtures select installed Edge or Chrome on Windows. All CI browser scripts passed with those system browsers; GitHub CI installs Chromium on Ubuntu.
- An initial `npm ci` against the active `node_modules` tree failed with Windows `EPERM` while removing a locked native binary. An isolated clean `npm ci` passed. `npm install --package-lock=false --ignore-scripts` restored the active dependency tree for the test run.
- Next’s SWC native module required a temporary cache under the user temp directory. The build passed with that cache. The demo route browser test also passed under the same cache owner.
- npm install printed 5 high and 5 moderate advisory counts. The repository audit passed its runtime gate and accepted the documented high severity ESLint tooling exception above; the moderate findings were not blocking in the CI workflow.

## Environment retries and cleanup

The first backend run used the Windows default pytest temp root and hit an access denied error. A later run used a temp directory created by a different Windows identity and hit the same ACL boundary. The final full run used a fresh temp directory created by the test process identity and passed.

The security migration and platform PostgreSQL checks initially used database names that their test guards reject. They passed when rerun with the exact CI database names. An initial public AI browser run timed out while backend checks were competing for local resources; it passed when rerun alone. The demo route harness initially failed because its child Next process could not access the SWC cache; it passed with the cache configured under the matching identity.

All six PostgreSQL databases created for this run were dropped. Generated pytest temp directories, the SBOM file, the temporary Node shim, and the demo route fixture output were removed. The Redis and Postgres containers that were already running were left running.

## Scope and limitations

This was a local Windows simulation of the current GitHub Actions workflows. GitHub Actions itself was not triggered. Browser checks used the system Windows browsers, and the local Node version differs from the workflow’s Node 20 pin. No failures remain in the final local runs.
